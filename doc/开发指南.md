## 技术架构

### 整体架构

```
┌─────────────────────────────────────────────────────────────┐
│  PyQt6 GUI 启动器 (main.py)                                  │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐   │
│  │服务管理  │  │部署维护  │  │模型管理  │  │软件更新  │   │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘  └────┬─────┘   │
│       │              │              │              │          │
│  ┌────┴──────────────┴──────────────┴──────────────┴─────┐  │
│  │              ServiceProcess (QThread)                  │  │
│  │    启动/停止/监控 后端和前端子进程                        │  │
│  └────┬──────────────────────────────────┬───────────────┘  │
└───────┼──────────────────────────────────┼──────────────────┘
        │                                  │
        ▼                                  ▼
┌───────────────────┐            ┌───────────────────┐
│  后端 (FastAPI)    │            │  前端代理 (FastAPI) │
│  launcher.py       │            │  _ui_server.py     │
│  ltx2_server.py    │◄──代理────│  静态文件服务       │
│  port: 3000(默认)  │            │  API请求转发       │
│                    │            │  port: 4000(默认)  │
└───────────────────┘            └─────────┬─────────┘
                                           │
                                    ┌──────┴──────┐
                                    │  浏览器访问   │
                                    │  index.html  │
                                    │  index.js    │
                                    └─────────────┘
```

### 三进程架构

| 进程 | 入口 | 框架 | 默认端口 | 职责 |
|------|------|------|---------|------|
| **GUI启动器** | `main.py` | PyQt6 | — | 服务管理、部署维护、系统托盘 |
| **核心引擎** | `launcher.py` → `ltx2_server.py` | FastAPI + Uvicorn | 3000 | AI推理API、模型管理、任务队列 |
| **UI工作站** | `_ui_server.py`（运行时生成） | FastAPI + Uvicorn | 4000 | 静态文件服务、API代理转发 |

### 启动流程

```
用户点击「启动全部」
  │
  ├─ 1. 启动后端核心引擎
  │     生成 launcher.py（注入端口、路径）
  │     启动子进程: python launcher.py
  │
  ├─ 2. 轮询等待后端端口就绪（最多90秒）
  │     每秒检测 127.0.0.1:{backend_port}
  │
  ├─ 3. 后端就绪后，启动前端UI工作站
  │     生成 _ui_server.py（注入端口、路径、图标base64）
  │     启动子进程: python _ui_server.py
  │
  └─ 4. 前端就绪后，自动打开浏览器（如启用）
        打开 http://127.0.0.1:{frontend_port}
```

### 关键类

| 类 | 职责 |
|---|------|
| `MainWindow` | 主窗口，包含所有UI和业务逻辑 |
| `ServiceMonitor` | 定时检测后端/前端端口状态 |
| `ServiceProcess` | QThread，管理子进程的启动/输出/退出 |
| `ConfigManager` | 配置读写（launcher_config.json） |
| `ServiceCard` | 服务状态卡片UI组件 |
| `ToggleSwitch` | 自定义开关组件 |

## 完整开发→打包→分发流程

### 开发阶段

```
1. 编辑 dev/app/main.py（GUI启动器）
   编辑 dev/app/resources/patches/（补丁与扩展）
   编辑 dev/app/resources/ui/（前端界面）
   编辑 dev/app/resources/backend/（后端代码）

2. 开发模式运行：
   python dev/app/main.py

3. 测试功能，确认无误
```

### 打包阶段

**方式一：版本化构建（推荐，--onefile 单文件）**

```bash
python dev/app/build-version.py 修改内容1 修改内容2 ...
```

自动流程：
1. 代码验证（语法检查、方法完整性、模板占位符检查）
2. 移除BOM标记
3. PyInstaller `--onefile` 打包
4. 创建发布目录（三目录结构：app/data/temp）
5. 生成 `resources.zip`（用于首次启动自举下载）
6. 记录版本到 `version_history.json` 和 `versions.json`
7. 部署EXE到 `dev/` 目录
8. Git提交并推送

**方式二：简化构建（--onedir 目录模式）**

```bash
python dev/app/simple_build.py
```

适用于快速测试，生成目录模式EXE（含 `_internal/` 目录）。

### 构建前验证

`build-version.py` 内置代码验证，打包前自动检查：

| 检查项 | 说明 |
|--------|------|
| Python语法检查 | 所有 `.py` 文件 |
| 方法完整性 | `main.py` 中调用的私有方法是否都已定义 |
| 关键方法存在性 | `_start_all`、`_stop_all`、`_log` 等核心方法 |
| 扩展模块导入 | `patches/extensions/` 下的模块是否可导入 |
| app_factory导出 | `create_app`、`DEFAULT_ALLOWED_ORIGINS` |
| 前端脚本模板 | 占位符 `__BACKEND_PORT__` 等是否完整 + `.replace()` 调用是否齐全 |

### EXE入口点

`launcher.py` 是EXE的入口文件，职责：
1. 终止旧版同名EXE进程（通过Windows API遍历进程列表）
2. 抑制stdout/stderr输出（EXE模式无控制台）
3. 导入并运行 `main.main()`

## 端口配置机制

### 端口存储

端口配置存储在 `data/config/launcher_config.json`：

```json
{
  "ports": {
    "backend": 3000,
    "frontend": 4000
  }
}
```

### 端口初始化

`MainWindow.__init__` 中从配置读取端口：

```python
self._backend_port = self.config.get("ports.backend", DEFAULT_BACKEND_PORT)  # 默认3000
self._frontend_port = self.config.get("ports.frontend", DEFAULT_FRONTEND_PORT)  # 默认4000
```

### 端口修改流程

用户在ServiceCard中修改端口时：

```
用户点击「修改」→ 输入新端口 → 点击「确定」
  │
  ├─ 1. 校验：不能与另一服务使用相同端口
  ├─ 2. 校验：新端口不能被占用
  ├─ 3. 停止当前服务（如运行中）
  │     terminate进程 → kill端口残留 → 等待端口释放
  ├─ 4. 更新实例变量和配置文件
  │     self._backend_port = new_port
  │     self.config.set("ports.backend", new_port)
  │
  ├─ 5a. 修改后端端口（如前端在运行）：
  │     启动后端 → 轮询等待后端就绪 → 重启前端（注入新后端端口）
  │
  └─ 5b. 修改前端端口：
        启动前端 → 轮询等待前端就绪 → 自动打开浏览器到新URL
```

### 端口注入机制

后端和前端的端口通过**运行时生成脚本**注入，不硬编码：

**后端**：`_start_backend()` 生成 `launcher.py`，包含：
```python
uvicorn.run(app, host="0.0.0.0", port={self._backend_port}, ...)
```

**前端**：`_start_frontend()` 生成 `_ui_server.py`，包含：
```python
BACKEND_PORT = __BACKEND_PORT__    # → str.replace("__BACKEND_PORT__", str(backend_port))
FRONTEND_PORT = __FRONTEND_PORT__  # → str.replace("__FRONTEND_PORT__", str(frontend_port))
```

前端JS中 `{{BACKEND_PORT}}` 占位符在请求时被替换：
```python
content = content.replace("{{BACKEND_PORT}}", str(BACKEND_PORT))
```

> **重要**：前端脚本模板必须使用 `__PLACEHOLDER__` 占位符 + `str.replace()` 方式注入值，
> 不得使用 f-string 插值，否则会导致花括号转义错误。

## 前端代理与API转发

### 为什么需要前端代理

前端（浏览器）和后端运行在不同端口，存在跨域问题。前端代理服务器解决此问题：

```
浏览器 → http://127.0.0.1:4000/api/xxx → 前端代理 → http://127.0.0.1:3000/api/xxx → 后端
浏览器 → http://127.0.0.1:4000/index.js  → 前端代理 → 返回JS（注入BACKEND_PORT）
浏览器 → http://127.0.0.1:4000/outputs/  → 前端代理 → 直接读取本地文件
```

### 前端JS的API调用方式

`index.js` 使用同源端口，不硬编码后端端口：

```javascript
const BASE = `http://${window.location.hostname}:${window.location.port}`;
// 所有API调用: fetch(`${BASE}/api/xxx`)
```

### 代理路由

| 路由 | 方法 | 处理 |
|------|------|------|
| `/` | GET | 返回 index.html（注入图标base64） |
| `/index.js` | GET | 返回 JS（替换 `{{BACKEND_PORT}}` 占位符） |
| `/index.css` | GET | 返回 CSS |
| `/i18n.js` | GET | 返回国际化脚本 |
| `/app-icon.png` | GET | 返回应用图标 |
| `/api/app-info` | GET | 返回应用名称和版本 |
| `/api/{path}` | * | 代理转发到后端 |
| `/outputs/{path}` | GET | 直接读取本地输出文件（支持Range请求） |
| `/health` | GET | 代理后端健康检查 |

### 媒体文件优化

`/api/system/file` 请求直接由前端代理读取本地文件，不经过后端转发，减少内存占用和延迟。支持 HTTP Range 请求（视频拖动进度条）。

## 版本管理

### 版本号格式

`YYYY.MM.DD.HHMM`（如 `2026.05.22.0105`）

- 由构建脚本 `build-version.py` 自动生成
- 注入到 `main.py` 的 `VERSION` 变量
- 记录在 `version_history.json` 和 `versions.json` 中

### 版本历史文件

| 文件 | 用途 | 格式 |
|------|------|------|
| `version_history.json` | 完整版本历史 | `{版本名: {version, changes, build_time, version_number}}` |
| `versions.json` | 版本列表（供软件更新页面） | `[{version, date, message, changes, name, download_url}]` |

### 版本描述规范

每次发布前应更新版本描述，构建脚本会交互式收集：

```bash
python build-version.py
# 请输入本次版本的修改内容：
# 1. 修复端口修改后前端无法正常运作
# 2. 添加端口释放等待机制
```

## 常见陷阱

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 修改后端端口后前端503 | 前端重启时后端尚未就绪 | 等后端端口就绪后再重启前端 |
| 前端脚本ValueError | f-string中花括号与JS模板冲突 | 使用 `__PLACEHOLDER__` + `str.replace()` |
| EXE启动后闪退 | launcher.py中stdout/stderr未抑制 | EXE模式使用 `_NullWriter` |
| 端口被占用无法启动 | 旧进程未完全退出 | `_kill_specific_port` + `_wait_for_port_free` |
| `_kill_port_processes`杀错进程 | 使用SERVICES字典（端口已更新） | 使用 `self._backend_port` 实例变量 |
| 修改前端端口后浏览器指向旧URL | 未自动打开新URL | 轮询前端就绪后自动 `_open_ui()` |
| 构建后EXE崩溃 | 代码语法错误或方法缺失 | `build-version.py` 自动验证 |
| 部署时模型下载慢 | HuggingFace国内访问受限 | 使用 HF-Mirror 国内镜像 |
| 前端跨域错误 | 浏览器直接访问后端端口 | 通过前端代理同源访问 |
