# 修改总结

## 问题1：Z-Image 模型描述获取失败

### 根因分析
- **HF API 401 错误**：ByteDance 官方仓库（如 `ByteDance/Z-Image-Turbo` 和 `ByteDance/Z-Image-Loras`）在 Hugging Face 上设置了**私有/受限访问**，API 返回 401 错误。
- **hf-mirror.com 308 重定向到 huggingface.co**：国内镜像只是重定向，最终还是回到 HF 服务器，同样遇到 401。
- **ModelScope 无对应模型**：ModelScope API 查询 `ByteDance/Z-Image-Turbo` 返回 "record not found"。
- **README.md 也无法访问**：同样的 401 限制。

### 解决方案
1. **增强 _hf_fetch_readme_desc()**：
   - 增加对 HF API `cardData.description` 的直接提取（即使 README 无法访问，cardData 有时仍可从公开页面获取）。
   - 兜底逻辑：当 README 和 cardData 都不可用时，不返回空，而是返回明确的 `{"description": "", "_no_desc": True}`。

2. **改进 _hf_fetch_modelscope()**：
   - 如果 ModelScope 有 `ChineseName`，将其拼接到描述前面，提供更友好的中文名称。

3. **前端优化**：
   - 当模型没有描述时，显示 `⚠ 暂无描述`（灰色提示），hover 时 tooltip 提示"该模型的描述信息不可用（可能仓库受限或无 README）"。
   - 这样用户可以清楚知道"是获取失败/仓库私有"还是"有描述"，而不是看到空白。

## 问题2：模型管理中出现 .pt/.bin/.pth 等非标准模型

### 问题描述
本地模型扫描时，扫描了所有 `.pt`、`.bin`、`.pth` 格式的 PyTorch 中间权重文件，这些不是独立的模型检查点，不应出现在模型管理表中。

### 解决方案
- **收窄扫描后缀**：只扫描 `.safetensors` 和 `.ckpt` 两种真正的模型文件格式。
- 影响范围：
  - `_scan_local_models()` 方法
  - `_populate_model_table_fallback()` 方法
- 效果：模型管理表不再显示无意义的 `.pt`、`.bin`、`.pth` 等中间权重文件。

## 问题3：模型名称列拖拽时只显示几个字母

### 问题描述
当鼠标拖拽挤压模型名称列宽时，列内容被压缩到只剩几个字母，用户体验差。

### 解决方案
1. **设置最小列宽**：`QHeaderView.setMinimumSectionSize(200)` - 拖拽缩小不会低于 200px。
2. **启用文本省略**：`QTableWidgetItem.setTextElideMode(Qt.TextElideMode.ElideRight)` - 当列宽小于文字宽度时，显示省略号（...），而不是挤成几个字母。
3. **描述列同样优化**：虽然描述列已经是 `Stretch` 模式，但也建议用户遇到类似问题时可以参考。
