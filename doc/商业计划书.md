### 核心论点(已与用户确认)

1. **"商业化护城河在云端 API,不在登录窗口"** —— 参考 Trae CN、Cursor、JetBrains Toolbox、VSCode、ComfyUI、Ollama 等所有主流桌面端 AI/创意工具的共识

3. **"客户端开源 ≠ 商业化受损"** —— 客户端价值有限,云端价值无限

**关键设计点(取 v1.0 + v2.0 之长)**:
- **客户端开源 ≠ 全部功能免费**:基础功能(生成视频、基础编辑、本地推理)完全免费开源;**高级功能**(批量、4K、TTS、多 LoRA)用卡密解锁

### 3.2 客户端:开源 + 免费

**开源策略**:

| 项 | 选择 | 理由 |
|---|---|---|
| **许可证** | **MIT + 商业附加条款**(参考 Elastic License v2) | MIT 太宽松,纯 MIT 同行随便改;Elastic License 禁止白嫖 SaaS |
| **商标保护** | "云集智能视频创意站" + Logo 注册商标 | 法律层面阻止同名派生 |
| **核心代码开源** | 启动器 + 前端 + 后端 Python | 获客 + 社区贡献 |
| **不公开仓库** | `vi.yunjii.cn` 私有仓,放云端 API + 鉴权 + 商业化代码 | 防止 token 伪造/商业策略泄露 |
| **开发模式** | 主仓放"稳定版",开发版在内部 | 同行 fork v1.0 时你已在 v3.0 |
| **贡献激励** | 贡献者名单、专属徽章、Plugin 收入分成 | 吸引开发者贡献 |

**许可证详细说明**:

采用类似 **Elastic License v2** 或 **SSPL(Server Side Public License)** 模式:
- ✅ 允许:个人/企业内部使用、修改、二次分发(需保留版权)
- ✅ 允许:基于此开发商业产品(不可使用"云集"商标)
- ❌ 禁止:提供托管服务竞争(SaaS 化本项目收费)
- ❌ 禁止:使用"云集"商标、Logo、品牌名

这样既保证开源精神,又阻止了"用你的代码做 SaaS 跟你竞争"。

#### 3.3.4 启动器高级功能门控实现(关键)

**门控策略**(从 v1.0 继承 + v2.0 简化):

```python
# 启动器 main.py(伪代码)
def check_pro_feature(feature_name: str) -> bool:
    """
    检查用户是否解锁某个高级功能
    - 免费版:基础功能可用,高级功能弹卡密购买提示
    - 卡密版:卡密有效期内全部解锁
    - 订阅版:订阅有效期内全部解锁
    """
    user_card = load_user_card_from_local_dpapi()  # 复用 v1 的 DPAPI
    if not user_card:
        return False  # 免费版
    
    if not is_card_valid(user_card):
        return False  # 卡密过期
    
    return True
```

**关键点**:
- 门控只在本地,代码完全开源(用户能看到门控逻辑)
- 但**没有有效卡密 = 没有 token = 调云端 API 失败**(云端兜底)
- **双层保险**:本地门控是体验优化(快速反馈),云端门控是安全底线(不可绕过)
- 参考 Cursor:客户端代码可见 + 云端 API 鉴权(同样的双层设计)

### 3.4 云端服务(核心增量收入,云电脑代理 + 云端 API 双模式)

> 这一节是 v2.0 商业计划的核心增量。**保留 v1.0 的"云电脑代理"模式**(对国内用户友好),**叠加 v2.0 新增的"云端 API"模式**(对开发者友好),双模式覆盖全部用户。

#### 3.4.1 为什么云端是核心

- 客户端再强,功能也是"生成视频"
- 视频生成 = GPU = 用户没 GPU 时只能来你这里
- 用户从本地起步 → 算力不够 → 切云端 → 这是自然转化漏斗
- **云端 = 经常性收入 + 高毛利 + 不可被同行白嫖**

#### 3.4.2 双模式架构

```
云端服务
│
├── 模式 A:云电脑代理(从 v1.0 完整继承,主力)
│   特点:用户看到"一台云端 Windows 电脑",完整桌面体验
│   适合:小白用户、没显卡、临时大算力
│   计费:按分钟/小时
│   厂商:AutoDL / 矩池云 / 恒源云(代理)
│
└── 模式 B:云端 API(从 v2.0 新增,扩展)
    特点:用户在本地启动器点"云端生成",不看到云端
    适合:开发者、专业用户、批量生产
    计费:按调用次数 / token 数
    厂商:自建 + 代理混合
```

#### 3.4.3 模式 A:云电脑代理(从 v1.0 完整继承,详细设计)

**核心思路**:**不自己买 GPU,代理云电脑厂商的算力,赚时间差价。**

**合作厂商优先级**(从 v1.0 完整继承):

| 优先级 | 厂商 | 优势 | 接入难度 |
|---|---|---|---|
| 1 | **AutoDL** | 国内最大、API 成熟、价格透明 | 低 |
| 2 | **矩池云** | 学术用户多、镜像丰富 | 低 |
| 3 | **恒源云** | 稳定、有企业版 | 中 |
| 4 | **趋动云** | GPU 池化技术 | 中 |
| 5 | **揽睿星舟** | 备选 | — |
| 6 | **其他** | 按需 | — |

**定价与利润模型**(从 v1.0 完整继承):

| GPU 档位 | 云电脑成本(批发) | 用户售价 | 毛利率 | 目标用户 |
|---|---|---|---|---|
| **T4 / 3060(16GB)** | ¥1.5/小时 | ¥3/小时 | 50% | 轻度使用、个人创作者 |
| **4090(24GB)** | ¥4/小时 | ¥8/小时 | 50% | 工作室、中度使用 |
| **A100(80GB)** | ¥12/小时 | ¥22/小时 | 45% | 训练、批量生产 |
| **H100(80GB)** | ¥25/小时 | ¥45/小时 | 45% | 企业、高端用户 |

**计费方式**:
- 按分钟计费(0.05-0.75 元/分钟,根据 GPU 档位)
- 不使用不收费(实例关闭后立即停止)
- 余额预付制(用户先充值,用多少扣多少)

**技术实现方案**(从 v1.0 继承,具体化):

```
用户启动器 → 点"云电脑模式"
  │
  ├─ 1. 检查卡密余额(从 v1.0 复用,无余额提示充值)
  │
  ├─ 2. 选择 GPU 档位(T4/4090/A100)
  │     显示当前排队人数 + 预计等待时间
```

### 4.2 LICENSE 选择

**推荐:Elastic License v2.0**

参考:[https://www.elastic.co/licensing/elastic-license](https://www.elastic.co/licensing/elastic-license)

核心条款:
- ✅ 允许:免费使用、修改、分发
- ✅ 允许:基于此开发商业产品(非 SaaS)
- ❌ 禁止:提供托管服务竞争(不能 SaaS 化)
- ❌ 禁止:绕过许可证限制
- ❌ 禁止:使用 Elastic 商标

**为什么不用 MIT/Apache 2.0**:
- 太宽松,同行可以无限制 SaaS 化
- 你做了云端 SaaS,被白嫖者用你的客户端代码做同样的 SaaS,直接竞争

**为什么不用 GPL/AGPL**:
- 太严格,企业用户不敢用
- AGPL 强制云端服务也开源,会限制你未来的云端商业化

**为什么不用 SSPL**:
- MongoDB 用的,但社区接受度不高
- 容易引发争议,反而不利于品牌

## 十一、对比 v1.0 / v2.0 商业计划书的关键差异

| 维度 | v1.0 (2026-06-03) | v2.0 初版(本计划第一稿) | **v2.0 终版(取长补短)** |
|---|---|---|---|
| 核心策略 | 时间卡密保护 + 云电脑代理 | 开源 + 云端 API + 插件生态 | **开源客户端 + 本地卡密 + 云电脑代理 + 云端 API + 插件生态 + 1对1 服务** |
| 防御 | 卡密 + 防破解 | 商标 + 持续创新 + 生态 | **商标 + 持续创新 + 生态 + 卡密(本地) + 双层鉴权** |
| 主要收入 | 时间卡密(月卡/季卡/年卡) | 云端 API 按量 + 企业订阅 + 插件抽成 | **卡密(月卡) + 1对1 服务 + 云电脑代理 + 云端 API + 企业版 + 插件市场** |
| 客户 | 终端用户 | 终端用户 + 企业 + 开发者 | **终端用户 + 小白云电脑用户 + 工作室 + 企业 + 开发者** |
| 增长 | 渠道推广 | 社区贡献 + 内容生态 + 品牌 | **社区贡献 + 卡密口碑 + 1对1 转介绍 + 云电脑规模化** |
| 启动期收入 | (未明确) | M1 0 → M3 亏 → M9 平衡 | **M1 0 → M2 平衡(¥4,500) → M6 ¥28,000 → M12 ¥118,000** |
| M12 收入 | ¥23,000 | ¥58,000 | **¥118,000** |
| M12 利润 | ¥12,300 | ¥16,300 | **¥70,000** |
| M24 收入 | (无预测) | ¥383,000 | **¥513,000** |
| 长期估值 | 工具型软件(天花板低) | 平台型生态(想象空间大) | **工具 + 平台 + 生态(三重护城河)** |

**v2.0 终版 = v1.0 实战经验 + v2.0 战略视野 + 用户的取舍**

**关键改善**:
- 收入来源:从 1 条 → **6 条**(卡密、1对1、云电脑、云端 API、企业版、插件市场)
- 启动期:从 M9 平衡 → **M2 平衡**(提前 7 个月)
- M12 收入:从 ¥23,000 → **¥118,000**(增长 5 倍)
- 防御:从单层(卡密) → **双层(本地卡密 + 云端 API)**
